# Aurora Mobile 后续开发计划

状态：Android v0.1.0 已发布；后续先修稳定性，再扩展功能。
本清单替代旧 M0 清单，区分已实现、待验收与计划项，不以测试总数代替功能验收。

## 第一阶段：稳定性修补版

| 项目 | 当前状态 | 下一步 | 验收标准 |
|---|---|---|---|
| 刷新错误后的卡住问题 | 已复现 HTTP 错误/超大响应的无期限 drain；本轮已修客户端并补测试 | 等用户补充报错后的具体现象，真机复测 | 错误及时返回；按钮恢复；继续刷新正常源成功；旧文章保留 |
| 刷新结果与重试 | 全量刷新有失败计数；单源刷新和后台任务的错误记录不统一 | 统一结果记录；列出失败的源与原因；只重试失败项 | 单源失败不阻断其他源；成功重试清旧错误；刷新页可关闭提示 |
| 请求预算与取消 | 普通下载有超时，但非整轮总时限；全量刷新串行 | 为单源设总时限，设计小并发队列及取消 | 慢源不长期挡住其他源；取消不丢已完成数据、不阻止下一轮 |
| 标题自动翻译 | 已接入条目构建回调，不是真实可见性；超过 3 个在途任务直接跳过 | 可见条目队列、去重、语言切换隔离、关闭开关后停止排队 | 第 4 条起不会永久漏翻；不翻离屏条目；不串语言；不重载第一页 |
| 阅读页与分享 | 阅读元数据溢出已修；分享卡片二维码为异步绘制，调用未等待 | 二维码生成完成再输出；iPad 分享锚点；长标题/长代码布局回归 | PNG 实际含可扫描二维码；截图只声称当前画面；复制图标不遮代码 |
| 数据保护与升级 | OPML 仅备份订阅；此前手工替换 SQLite 出过主库/WAL 不匹配 | 禁止以手工换库作为常规导入；检查发布签名固定化并备份密钥 | 连续两个构建可覆盖升级、数据保留；签名不依赖 CI 临时 debug key |

发布门槛：上述关键回归通过；Android 真机完成失败后重试、离线阅读、覆盖升级；发布说明标明剩余限制。不直接修改已发布 APK 冒充原版本。

## 第二阶段：阅读与数据完整性

| 功能 | 当前状态 | 验收标准 |
|---|---|---|
| 文章进度记忆 | 只有 prefs 存取方法，阅读页尚未接入 | 长文重开定位；图片延迟加载后不跳错；切换原文/全文策略明确 |
| 衬线字体 | 只有 prefs 存取方法，阅读设置尚未接入 | 中英文与字号/行距组合正常；重启保留；系统大字体无溢出 |
| 播客续听 | 已实现基础保存/恢复，待强化 | 持久键稳定；退出及时保存；完成状态和加载失败可恢复 |
| 全量备份恢复 | 未实现，OPML 不等同数据库备份 | 一致性快照包含文章/收藏/已读；恢复先校验；不默认导出 API Key |
| 图片缓存与保存 | 已接入下载与相册写入 | 拒绝权限有反馈；下载有超时与体积限制；失败释放连接 |
| 阅读器错误处理 | 部分友好错误提示已实现 | 区分超时、空内容、HTTP 错误、JS 页面；不把所有非 200 都定为反爬 |

## 第三阶段：按真实需求扩展

- iPad：先修运行与分享问题，再做宽屏导航和双栏阅读；Apple 商店分发暂缓。
- 后台刷新：HyperOS 长周期、通知权限、电池约束实测；不承诺精确到点刷新。
- 自定义 AI 提示词、摘要与翻译分模型：基础翻译队列稳定后再做。
- 收藏标签、批量整理：依据用户实际整理工作流决定。
- 视频：维持卡片与外部打开，内嵌播放低优先级。
- RSSHub：作为标准 RSS/Atom 全 URL 接入，不新增平台专有接口。
- 赞助：GitHub 分发继续免费；IAP 留待 Apple 分发计划确定后评估，不提前接支付。

## 尚未完成的验证

- 自签名、过期证书等 TLS 测试语料；必须保留默认拒绝不可信证书。
- OPML 手动冒烟（已有清单，不代表已执行）。
- Android 50k 真机基准；主机结果不替代真机结果。
- iOS/iPad 日常启动、权限和分享验证；编译/安装/启动命令成功不等同完整验收。

## 现阶段不做

- 官方账号或强制云同步。
- 为了展示效果而伪造内容、缓存状态、加载成功截图。
- 以禁用 TLS 验证、绕过网站访问限制作为提取修复方案。
